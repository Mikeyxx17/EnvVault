# EnvVault 构建说明

本文说明如何在另一台电脑上用 GitHub 源码编出 `envvault`、装到 `PATH`，以及构建期 / 运行期环境变量分别是什么。

仓库当前只提供源码，没有官方预编译安装包。`Cargo.toml` 里 `publish = false`，不能 `cargo install envvault` 从 crates.io 安装。

当前版本尚未完成生产安全验收，编出来的程序也不能当作生产 Secret 保险柜。

完整命令用法见 [EnvVault使用命令与产出文件说明.md](./EnvVault使用命令与产出文件说明.md)。

## 1. 另一台电脑要准备什么

| 软件 | 要求 | 说明 |
|---|---|---|
| Git | 能 `git clone` | 用来拉源码 |
| [rustup](https://rustup.rs/) | 建议用 rustup 管理工具链 | 不要只装过期的发行版 `rustc` |
| Rust | **1.97 或更高** | `Cargo.toml` 的 `rust-version = "1.97"`；CI 用 `1.97.1` |
| C 链接器 | Linux：`build-essential`；macOS：Xcode CLT；Windows：MSVC 构建工具 | 编依赖时需要 |
| 网络 | 第一次编要拉 crates | 之后可用 `--offline`（见下文） |

仓库根目录 `rust-toolchain.toml` 指定 `1.97.1`，并带上 `clippy`、`rustfmt`。进入仓库后 rustup 会按该文件选工具链。

查看本机是否够用：

```bash
git --version
rustup --version
rustc --version          # 应 >= 1.97
cargo --version
```

### 1.1 安装 Rust（还没有 rustup 时）

按 [https://rustup.rs/](https://rustup.rs/) 的官方脚本安装。装完后确认 `~/.cargo/bin` 已在 `PATH` 里（见第 4 节）。

进入本仓库后再装项目声明的组件：

```bash
cd EnvVault
rustup show
rustup component add clippy rustfmt
```

### 1.2 各平台额外说明

这些**不是编译所必需**，只影响 `keystore` / `--machine-unlock` 运行时：

| 平台 | 构建 | 运行 machine unlock |
|---|---|---|
| Linux | 一般只需 `gcc`/`ld`（`sudo apt install build-essential pkg-config`） | 登录会话里要有 Secret Service（常见是 `gnome-keyring`）和可用的 `DBUS_SESSION_BUS_ADDRESS` |
| macOS | Xcode Command Line Tools | 系统钥匙串；测试时不要把临时目录放在 `/var` 这类符号链接祖先上 |
| Windows | Visual Studio 的 C++ 桌面开发 / MSVC | Windows Credential Manager |

没有钥匙库，普通 `init` / `set` / `run`（交互输 Master Password）仍可编译、可运行。

## 2. 获取源码并构建

```bash
git clone https://github.com/Mikeyxx17/EnvVault.git
cd EnvVault
```

只编可执行文件：

```bash
# 调试版：快，二进制在 target/debug/envvault
cargo build

# 发布版：优化 + LTO，二进制在 target/release/envvault
cargo build --release --locked
```

`--locked` 使用仓库里的 `Cargo.lock`，和 CI 一致，避免依赖版本漂移。

验证：

```bash
./target/release/envvault --version
./target/release/envvault --help
```

应输出 `envvault 0.1.0`。

建议的本地检查（与 `CONTRIBUTING.md`、CI 对齐）：

```bash
cargo fmt --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features --locked
```

macOS 上跑测试时，把临时目录指到非符号链接路径，否则路径安全检查会拒绝：

```bash
export TMPDIR="${TMPDIR:-$HOME/tmp}"
mkdir -p "$TMPDIR"
cargo test --workspace --all-features --locked
```

CI 里对应的是 `TMPDIR` 设为 runner 的临时目录。

### 2.1 装到 PATH

```bash
mkdir -p ~/.local/bin
cp target/release/envvault ~/.local/bin/envvault
# 确认 ~/.local/bin 在 PATH 中（见第 4 节）
envvault --version
```

不要把 `target/`、`*.vault*`、`*.credential.json`、`.env` 提交或拷到公开仓库。

### 2.2 离线再编

已经成功编过一次、crates 还在本机缓存里时：

```bash
cargo build --release --locked --offline
```

缓存默认在 `$CARGO_HOME/registry`（未设置时是 `~/.cargo/registry`）。换一台全新机器没有缓存，第一次不能离线。

### 2.3 可选：fuzz（日常使用不需要）

fuzz 是独立的 `fuzz/` crate，要 nightly 和 `cargo-fuzz`。主程序用 stable 即可。定时 CI 使用的 nightly 见 `.github/workflows/fuzz.yml`。个人把 CLI 装到另一台电脑，**不必**编 fuzz。

## 3. 环境变量：分三类

EnvVault **没有** `ENVVAULT_PASSWORD`、`ENVVAULT_SECRET` 这类变量。Master Password 和 Secret 值只能从交互终端输入，这是故意的。

### 3.1 构建 / 工具链（编程序时）

这些是 Rust / 系统的变量，不是 Vault 里的密钥。

| 变量 | 谁读 | 作用 | 个人用要不要设 |
|---|---|---|---|
| `PATH` | shell | 找到 `cargo`、`rustc`、`envvault` | 必须能找到 rustup 和安装后的 `envvault` |
| `CARGO_HOME` | cargo | Cargo 主目录（registry、bin、env） | 一般不用设，默认 `~/.cargo` |
| `RUSTUP_HOME` | rustup | 工具链安装位置 | 一般不用设，默认 `~/.rustup` |
| `RUSTUP_TOOLCHAIN` | rustup | 强制某个工具链 | 通常不设，交给 `rust-toolchain.toml` |
| `RUSTFLAGS` | rustc | 额外 rustc 参数 | 日常不要设 |
| `CARGO_TERM_COLOR` | cargo | 是否彩色输出 | 可选 |
| `CARGO_NET_OFFLINE` | cargo | 等价于 `--offline` | 可选 |
| `TMPDIR`（Unix） / `TEMP`、`TMP`（Windows） | 测试与部分 crate | 临时文件位置 | macOS 跑测试时若 `/var` 是 symlink，应改到真实目录 |
| `DBUS_SESSION_BUS_ADDRESS` | Linux 钥匙库 | 会话总线 | 图形登录一般已有；纯 SSH 可能没有，只影响 keystore |

装 rustup 后常见的是在 `~/.bashrc` 或 `~/.profile` 里：

```bash
# rustup 默认会写类似这一句
. "$HOME/.cargo/env"

# 若把 envvault 拷到了 ~/.local/bin
if [ -d "$HOME/.local/bin" ]; then
    case ":$PATH:" in
        *":$HOME/.local/bin:"*) ;;
        *) export PATH="$HOME/.local/bin:$PATH" ;;
    esac
fi
```

改完执行 `source ~/.bashrc`，或新开一个终端。`~/.profile` 只对登录 shell 生效，图形终端若只读 `.bashrc`，要把 `~/.local/bin` 写进 `.bashrc`。

**不要**把 Master Password 或任何 Secret 写进 `.bashrc`。

### 3.2 运行 EnvVault 本身（你敲 `envvault` 时）

CLI **不**从环境变量读取：

- Master Password
- Secret Value
- credential 原文
- Vault 路径（路径来自 `--vault` 或当前目录往上的 `envvault.json`）

因此下面这些**不存在、也不要自己发明**：

```text
ENVVAULT_PASSWORD
ENVVAULT_MASTER_PASSWORD
ENVVAULT_SECRET
ENVVAULT_VAULT
```

`run --machine-unlock` 走操作系统钥匙库，也不是读某个密码环境变量。

### 3.3 `envvault run` 启动子程序时（注入给别人的进程）

`run` 会 **清空父进程环境**，再只放回一份白名单，加上 Profile 里授过权的变量。

Linux / macOS 白名单：

```text
PATH
HOME
TMPDIR
LANG
CARGO_HOME
RUSTUP_HOME
```

Windows 白名单：

```text
SystemRoot
WINDIR
ComSpec
PATHEXT
PATH
TEMP
TMP
USERPROFILE
LOCALAPPDATA
APPDATA
CARGO_HOME
RUSTUP_HOME
```

因此：

- 你在 shell 里 `export FOO=bar`，子程序默认**看不见** `FOO`。
- 要让子程序拿到某条 Secret，必须：Vault 里 `set` 过 → 写入 Profile → `policy grant-use`。
- 子程序用语言自己的 API 读环境变量即可（例如 Rust 的 `std::env::var("TEST_TOKEN")`），不要读 Vault 文件。
- 白名单里的 `CARGO_HOME` / `RUSTUP_HOME` 是为了子进程还能调用 `cargo`，不是用来传密钥。

测试代码里会出现 `ENVVAULT_*_TEST_*` 这类名字，只给自动化测试用，不是给用户配置的接口。

## 4. 编完后在新机器上的最小使用

```bash
cd /path/to/your-app
envvault init                 # 创建 .envvault/vault 和 envvault.json
envvault set TEST_TOKEN       # 终端里输入值，不要写进环境变量
envvault identity register --kind application --name my-app
envvault profile create TEST_TOKEN
envvault policy grant-use
envvault run -- ./my-app
```

Vault 和密钥**不会**跟着 GitHub 仓库走。换电脑要么重新 `set`，要么私下拷贝该项目的 `.envvault/`（不要提交 git）。

## 5. 常见构建问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `error: package rustc is too old` / edition 2024 | Rust < 1.97 | `rustup update`，确认 `rustc --version` |
| `error: no matching package named …` 且用了 `--offline` | 本地没有 crate 缓存 | 去掉 `--offline` 先成功编一次 |
| `linker 'cc' not found` | 没装 C 工具链 | Linux 装 `build-essential` |
| `envvault: command not found` | 没拷到 PATH，或终端没 source | 用 `./target/release/envvault`，或按 2.1 / 3.1 设置 |
| 测试在 macOS 报不安全路径 | `/var` 等是 symlink | 设置 `TMPDIR` 到真实目录 |
| `keystore` / `--machine-unlock` 失败 | 没有登录会话钥匙库 | 先用交互 Master Password；Linux 检查 gnome-keyring 与 DBus |
| 想从 crates.io 安装 | `publish = false` | 只能 clone 源码构建 |

## 6. 不要提交、不要打包进发布物的内容

- `target/`
- `*.vault*`、`.envvault/`、`*.credential.json`
- `.env`（可以提交 `.env.example`，且必须没有值）
- fuzz 运行产物：`fuzz/artifacts/`、`fuzz/coverage/`、`fuzz/runs/`
- 真实密钥、密码、credential

构建文档和源码可以进 git；Vault 不能。
